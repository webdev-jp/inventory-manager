01

Quick start

Inventory Manager tracks every device the organization owns — who has it, its serial number, software profile and Active Directory status — and does the day-to-day AD lifecycle work (onboard, transfer, offboard) without leaving the app. Several admins can use it at once on the same data (§10).

Add a new hireFile → Onboard New User (§5)
Give someone a different computer, manager or OURight-click the device → Transfer User (§6)
Offboard someone nowRight-click → Offboard User (§7)
Offboard someone laterRight-click → Schedule Termination (§7.3)

02

Installing & setup

Install once: open \\fileserver01\IT-Apps\InventoryApp\ and double-click InventoryManager.App.application. Windows installs it and adds a Start Menu shortcut (Contoso Ltd → Inventory Manager). After that it checks the same folder at every launch and offers updates automatically. The install is signed with the "Contoso IT Scripts" certificate, which must already be trusted on the PC (it is on admin machines).

One-time setup per PC — shared data

Without this, the app quietly works from a private local copy and you won't see other admins' data. From an elevated prompt (Run as administrator — cmd or PowerShell), run:

setx INVMGR_DATA_DIR "\\fileserver01\IT-Apps\InventoryAppData" /M
setx INVMGR_SECURITY_LOG_DIR "\\fileserver01\IT-Apps\InventoryAppData" /M

Then restart the PC (log off/on usually works, restart is more reliable) — a running Windows session doesn't see new variables.

If the setup doesn't seem to work
  • Don't put a backslash before the closing quote (...InventoryAppData\"). Windows reads \" as an escaped quote, so the /M gets swallowed into the value and the setting is silently corrupted.
  • It must be elevated. A non-elevated prompt fails with "Access is denied" and changes nothing.
  • A user-level copy of the variable overrides the machine-wide one. If an earlier attempt left a bad one, remove it (no elevation needed), then restart:
    [Environment]::SetEnvironmentVariable("INVMGR_DATA_DIR", $null, "User")
    [Environment]::SetEnvironmentVariable("INVMGR_SECURITY_LOG_DIR", $null, "User")
  • Variable set but wrong or unreachable: the app warns at launch, naming the variable and why. Variable not set at all: there's no warning — you just see an empty inventory.
  • Every launch is recorded in \\fileserver01\IT-Apps\InventoryAppData\startup-diagnostics.jsonl (what the app saw for each variable and where it ended up saving), which is the quickest way to diagnose a PC remotely.
03

Logging in

Two prompts appear before the main window. Both must succeed; you get 3 attempts at each, and cancelling closes the app.

  1. Access Gate. The username is locked to the shared gate account (inv-gateaccount) — type its password. This only proves you were given the shared password.
  2. Admin Login. Enter your own AD admin account and password. It must be a member of the InventoryManager AD group, or you'll see "valid AD account but not a member… Access denied."

From then on, every AD change this session makes runs as your own account — that's what shows up in AD Notes. To act as someone else temporarily use File → Run AD Actions As...; File → Use My Windows Session for AD switches back.

The line under the search box summarizes the whole tab (e.g. "322 total, 4 no Serial #, 1 AD-disabled…"), whatever you've typed into Search.

Servers: moving a device into or out of Servers — or right-click → Mark as Server — never touches Active Directory (no enable/disable, no OU move). Mark as Server also excludes the device from AD Sync; a plain Move to → Servers does not.

Users with no Devices

Starts empty. Click Refresh from AD to list every enabled AD user who has no device. Someone "has a device" if any inventory row — on any tab except IT Stock and Disabled Devices — matches them by Username, or by Last + First Name for older rows. Accounts with no first or last name (service accounts) are skipped. Select users and click Import Selected to create a placeholder record for each in Current Inventory (Device Name "No PC") to fill in later. The list re-queries after an import. There's no Add/Edit, Move to or right-click menu on this tab.

Protected admin accounts

The app doesn't change administrative accounts. An account is protected if it belongs (directly, nested or as primary group) to a privileged AD group (Domain/Enterprise/Schema Admins, Administrators, the Operators groups, DnsAdmins), if its name contains "admin", or if it's an SU account ("su" + another account's name, e.g. sujdoe). For those: they aren't listed in Users with no Devices, the AD Notes mirror skips them, and Transfer User, Offboard User, Schedule Termination and Copy User Permissions (as target) refuse and tell you to use ADUC. If AD can't be reached to check, every account is treated as protected.

Grid, search and sort

  • Columns shown: Device, Last Name, First Name, Laptop Model, Serial #, Domain, ESET Profile, Splashtop Profile, Cellphone #, Cellphone Model, Description, Username. The other fields (Admin Profile, Docking, monitors, Topaz) are in the full record — double-click a row or right-click → Edit Item.
  • Search filters the tab live across every visible field; ✕ clears it. Click a header to sort (click again to reverse). Your sort, selection and scroll position survive the background refreshes.
  • Duplicates: a device recorded more than once shows ▶/▼ and "(+N other user(s))" — click the Device cell to expand or collapse the group.

Adding and editing records

Add Item and Edit Item (also used when you move a device to Current Inventory) open the full record. The Username matches itself: as soon as you finish typing the Last Name and First Name, the app looks the person up in AD and fills in the Username, with a line under it such as "Matched to Alice Jones (ajones)". You never need Match User for a record you're entering.

  • Several people fit (two Smiths and no first name, or two with the same name), or the first name doesn't match the only person with that last name (typing "Rob" when AD has "Bob Brown"): nothing is filled in. The line under the Username tells you, and Change… opens a search (pre-filled with the name) where you pick the right person. A doubtful match is only ever suggested, never applied.
  • Change… also fixes a wrong match — pick a different person and the Username and name follow.
  • An existing link is left alone when you open a record. It's only re-matched if you change the name, and if the new name finds nobody, the old link stays (the line says so).

Use the Move to dropdown + Move, or right-click → Move to. Moves also change the computer in AD:

The Edit Item form opens so you can enter the new user — nothing is written until you click OK; Cancel leaves everything as it was.
Current Inventory → any other tabThe computer is always disabled and moved to the Disabled Computers OU.
Between IT Stock, Disabled Devices and Computer Not in ADDisabled and moved only if it's still enabled.

Moving a device out of a status also clears the AD flag that put it there, so the next AD Sync doesn't flag it straight back. Import CSV / Export CSV bulk-load or export the current tab.

05

Onboarding a user

File → Onboard New User... (Ctrl+N) opens a 7-step wizard. Finishing is a real, immediate AD write — creating the account, adding the groups and creating the inventory record.

  1. Basic Info — ticket #, first/last name, Description, Office, Job Title, Department and Company (defaults to "Contoso", locked unless you tick Change Organization). The standard logon script is set automatically.
  2. Account Details — account name (suggested, editable), the login/email preview, a temporary password (entered twice) and "must change at next logon" (on by default).
  3. Organizational Unit — pick the OU and the person's manager.
  4. Security Groups — a searchable list; tick as many as needed. Domain Users is automatic. Privileged groups are hidden unless you're logged in as one of two authorized SU accounts (supattersonb, sudmorgan).
  5. Computer Assignment — type the device name or Browse… (only IT Stock and Disabled Devices are listed; the list shows each one's Description so you can spot a stale assignment). If it's already assigned to someone, you must confirm.
  6. Inventory Details — ESET, Splashtop, phone, etc.
  7. Review & Create — summary, then Finish.
Which groups count as privileged?

Matched by well-known ID (rename-proof): Domain Admins, Schema Admins, Enterprise Admins, Group Policy Creator Owners, Key Admins, Enterprise Key Admins, Administrators, Account Operators, Server Operators, Print Operators, Backup Operators.

Matched by name only (a rename would slip past): DnsAdmins, Cert Publishers, Organization Management, Exchange Trusted Subsystem, Exchange Windows Permissions, Enterprise Read-only Domain Controllers.

06

Transferring a user

Right-click a device → Transfer User. One dialog covers everything; a ticket # is required and you see a confirmation of exactly what will change before anything is written.

  • Manager, Organizational Unit and Computer — each is either "Browse" to a new value or "No change". The computer list shows devices with a blank Description plus every Disabled Devices device (with its Description, so a stale assignment is visible).
  • Description and Office — editable, pre-filled from AD.
  • If the device has no linked AD user, only the Computer can be transferred — run Match User first for the rest.

When the computer changes, the person's identity moves with them: Username, Description, Cellphone # and Cellphone Model. The old device is left with none of the person's details. Then:

  • New computer already enabled in AD: nothing else happens.
  • New computer disabled (or not found): it is enabled, and the old computer is disabled, moved to the Disabled Computers OU and marked Disabled Devices.
07

Offboarding a user

7.1 Offboard now

Right-click a device with a linked AD user → Offboard User. Inventory Manager launches the standalone Offboarding2026.ps1 tool with the username already searched, and hands it your SU credentials so its AD changes run as you. Do your offboarding in the tool, then close it. (Before launching, the app checks the script's digital signature; if it reports a failed check, reinstall or update the app.)

When you close it, Inventory Manager reads what the tool actually did before offering anything:

What happened in the toolWhat Inventory Manager does
Closed without running, cancelled, or Test Mode onlyNothing. The device is left unchanged.
No result came back (crashed or killed)A warning. Nothing is changed.
Real run, but for a different userA warning naming who. The device is left alone.
Real run for this device's userThe three-choice dialog below.
  • Finish offboarding — disables the computer in AD, stamps its Description with the ticket, moves it to the Disabled Computers OU, clears the device's user fields, marks it Disabled Devices, and adds a note (ticket, device, who) to the user's AD Notes.
  • Undo offboarding… — reverses what the tool did to the user after a second confirmation (default No). The device and computer aren't touched.
  • Decide later — changes nothing; finish by hand later with Move to → Disabled Devices. If any step failed, this is the default button so Enter can't finish a problem offboard.

The record stays locked to you while the tool is open (and through an undo).

What Undo puts back — and what it can't
  • Put back: AD account re-enabled; Description, OU, group memberships and address-book visibility; mailbox converted back to regular; forwarding, auto-reply and ActiveSync/OWA/IMAP/POP settings; manager access this offboarding granted is removed; removed licenses re-assigned. A delta sync runs at the end.
  • Can't be put back (listed for follow-up): the randomized password (reset it and give the user the new one), revoked sign-ins (harmless — they just sign in again), and an OneDrive archive (the files are in the archive folder and the OneDrive recycle bin).
  • Anything that fails (e.g. a license with no free seat) is listed as "could not be restored — fix by hand"; the rest still goes through. Undo is only available right after the tool closes; Decide later gives it up. Sign-in windows for Exchange/Graph/SharePoint may appear.

7.2 Inside the offboarding tool

Pick the steps (or a Preset), fill in Manager UPN/email and Ticket # (required for a real run), and click Run. TEST MODE is on by default — every step logs "WOULD: …" and nothing changes, but read-only checks still run so problems (no mailbox, a license that can't be removed, an unreachable OneDrive) show up first. Run once in Test Mode, then untick it and run for real. Every run writes a transcript and CSV summary to C:\Temp\Offboarding\.

The steps, in order (✓ = on by default)
TabStep
Active DirectoryDisable account · Randomize password · Stamp description with date + ticket (keeps the old text after "Was:") · Hide from GAL (only if the schema has Exchange attributes) · Export group memberships to CSV · Remove all group memberships · Move to Disabled Users OU · Trigger ADSync delta syncall ✓
MailboxExport mailbox permissions to CSV ✓ · Convert to Shared + hide from address lists ✓ · Forward mail to manager · Enable auto-reply · Grant manager Full Access + SendAs · Disable ActiveSync/OWA/IMAP/POPfirst two ✓
CloudRevoke Entra sign-in sessions ✓ · Archive OneDrive to SharePoint · Grant manager access to OneDrive · Remove directly-assigned M365 licenses (runs last)first ✓

Steps that need a manager require the Manager field. Choosing both Archive OneDrive and Grant manager access warns you (the manager would get an empty OneDrive).

  • Failures are real: a failed step is marked FAILED and counted, never logged as done.
  • License removal is blocked unless the mailbox is already Shared, under 50 GB, with no litigation hold and no archive mailbox — otherwise it would be deleted after 30 days. The log says what blocked it. Group-based licenses are left alone and listed; remove the user from that group instead.
  • OneDrive archive deletes only after verifying: each item is copied and size-checked; originals go to the recycle bin only if every item verified.
  • While a run is in progress the window is locked and can't be closed.

Admin note: the Disabled Users OU must stay inside the Entra Connect sync scope. If it's ever removed, the Move + Delta sync steps would soft-delete the user in Entra ID, taking the shared mailbox and OneDrive with them.

7.3 Schedule a termination

Right-click a device with a linked AD user → Schedule Termination…, then pick the date and time (default tomorrow 5:00 PM), the ticket # (required) and optional notes. Nothing runs by itself. When it's due, the next admin who has the app open — or opens it — gets a "Scheduled Terminations Due" window with Offboard Now…, Edit… and Cancel Schedule…. Offboard Now starts the normal §7.1 flow with that admin's own logins, so no credentials are ever stored. If it's dismissed, it returns every 30 minutes while still due, and at the next launch.

  • File → Scheduled Terminations… lists everything pending, soonest first (the menu shows how many are pending/due). Right-clicking someone who already has one shows Edit Scheduled Termination….
  • One schedule per person, kept under the AD username — transferring the device doesn't lose it.
  • Clicking Offboard Now claims the entry, so another admin isn't prompted for the same person (a claim from a crashed session expires after 2 hours). It's marked completed once the tool reports a real run for that user, however it was started.
  • If nobody has the app open at the due time, nothing is missed — it shows as overdue and prompts the next time it's opened. It is deliberately not an unattended, exact-time job.
  • Scheduling writes nothing to AD or AD Notes. The list is the shared file scheduled-terminations.json next to inventory.json. Protected accounts can't be scheduled.
08

AD Sync & the File menu

Active Directory Sync

File → Active Directory Sync... checks every inventory record against AD and shows five tabs: User Disabled, User Not Found in AD, Computer Disabled, Recent AD Changes (30 days) and Computers Not in Inventory (with one-click import). It is a real save — it can move devices between tabs and update their AD flags. Rows set to Exclude from AD Sync are skipped entirely. A device with no matching AD user is flagged (red) but not moved. Each run logs a summary plus one line per device it actually changed. The right-click Check AD does the same check for just your selection and ignores the exclusion.

Other File menu items

  • Search Active Directory… — a standalone AD user lookup.
  • Find Duplicate Devices… — jump to devices recorded more than once, or delete the extra.
  • Import Cell Phone Numbers… — pick a carrier CSV (needs "User name" and "Wireless number" columns; "Device model" optional) and match it to Current Inventory by person name. Review tabs: Matched (exact matches, current vs incoming side by side; all pre-selected — nothing is written until Apply Selected), Ambiguous (a name matched several people — choose one or leave on "(skip)") and Unmatched (shared lines like "FRONT DESK PHONE", or people not in Current Inventory; informational). Names of any word count are matched against real First/Last Names, so "Jean Paul Francois" works.
  • Copy User Permissions… — pick a user to copy from and one to copy to, Scan, tick what to copy (currently AD group membership) and Apply Selected. It only adds — nothing is removed from the target. Also on the right-click menu. Export CSV saves the result.
  • Scheduled Terminations… — see §7.3.
09

Logs & backups

  • Backups. The data is snapshotted at startup and every 5 minutes when something changed (the 5 most recent are kept). File → Restore from Backup… rolls back to a chosen point — your current data is backed up first, so a restore is itself undoable. File → Open Backups Folder opens the folder.
  • Activity Log (collapsible panel on the right). Everything done this session — opens, saves, cancels, moves, imports, AD Sync results, refusals, logins and logouts. It also shows other admins' activity live (checked about every 15 seconds; each line is tagged with the SU account). Clear Log only clears the screen; Open Logs Folder opens the files.
  • Security Log (Security menu). A tamper-evident ledger of logins/logouts, login and gate failures, privileged-group grant attempts, refusals (protected accounts, honeytokens, script signature) and termination scheduling events. Each entry is chained to the one before, so Verify Security Log reports "TAMPERED" if anything was altered or deleted. It's for after-the-fact investigation, not daily checking.
  • Inventory Change Log (Security menu). A second tamper-evident ledger: every field changed on any record, by whom and when, one entry per changed field, never trimmed. Right-click → View Change History… pulls one device's complete history. If the record has a linked username, a short copy is also appended to that user's AD Notes (ADUC → Telephones tab) — AD caps Notes at about 1000 characters, so old entries roll off there; the local log is the record of record. A failed AD Notes write shows as a warning in the Activity Log.
    • Description changes also push to the linked AD computer's Description.
    • Username changes (a device changing hands) write each affected person a plain note instead: "{device} was removed from your assigned inventory by {you}" / "…was added to…".
10

Other admins at once

Several admins can work on the same shared data at the same time (this needs the setup in §2 on every PC).

  • Live refresh: every session picks up other admins' saved changes about every 15 seconds ("Inventory refreshed automatically…" in the Activity Log).
  • Record locking: Edit Item, Transfer User and Offboard User claim that one record. Anyone else opening it sees "'{device}' is currently being edited by '{admin}' … Try again in a few minutes." The lock releases when you close the dialog (saved or cancelled), and expires on its own after 30 minutes if a session crashes. Onboarding doesn't lock anything — it always creates a new record.

Troubleshooting

You see…It means / do this
An empty inventory, or you can't see other admins' dataThe shared-data setting isn't applied on this PC — §2.
"Record Locked"Another admin has that exact record open. Wait a few minutes.
"This record no longer exists"Someone deleted it since your last refresh.
"Could not save — the inventory file has been locked by another user for too long"Another save is taking unusually long. Your changes are safe; retry.
"Onboarding Blocked"A policy stop (disallowed OU, no manager, unauthorized privileged group). Nothing was changed.
"N privileged group(s) hidden"You aren't one of the two accounts allowed to grant privileged groups. Ordinary groups are unaffected.
"…is a protected administrative account"The app won't change admin accounts — use ADUC. See §4.
"The offboarding script failed its signature check"The script was changed or isn't trusted on this PC. Nothing ran. Reinstall or update the app; tell IT if it persists.
Delta sync "Access is denied" on ADSYNC01Neither your SU account nor your Windows account can remote into the sync server. The change still reaches the cloud on the next scheduled sync (about 30 minutes).

Good to know: the AD domain, SU group name, gate account and default OUs are built into the app (no settings screen) — changing them takes a new build. Offboarding is handed to the signed Offboarding2026.ps1, which must ship alongside the app.

What's changed lately

  • 2026-10-14 — Schedule Termination (§7.3). The Username now matches itself in Add/Edit, with a Change… button (§4). Removed Clear Username and Pull/Push Description to AD (Description still pushes to AD automatically when you save). This guide was also shortened and reorganized.
  • 2026-10-08 — The offboarding tool no longer freezes on hidden "untrusted publisher" prompts; the app now checks the script's signature itself before launching it.
  • 2026-10-01 — Protected admin accounts (§4); "No PC" placeholder rows are no longer treated as computers by AD Sync.
  • 2026-09-30 — Offboarding: the app checks what the tool actually did, plus Undo (§7.1); a ticket is required; sign-in revocation is on by default.
  • 2026-09-25 — "Users with no Devices" tab. The setup command was corrected (no trailing backslash, §2).
  • 2026-09-24 — Servers tab and Mark as Server.
  • 2026-09-23 — Import Cell Phone Numbers; Move to Current Inventory now writes nothing until OK; the Terminated, Unknown and User Not in AD tabs were removed (a terminated user's device goes to Disabled Devices); the Activity Log shows other admins' activity.

The detailed engineering history behind these changes is kept separately (docs\MaintainerNotes.md) and isn't part of this guide.
